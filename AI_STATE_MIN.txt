Canonical enums/constants:
SUPERVISOR_TITLES=["Batt. Chief","Div. Chief","Captain","Lieutenant","MOF"]
employeeTitleOptions=["Batt. Chief","Div. Chief","Captain","Lieutenant","Engineer","MOF","FF/EMTP","FF/EMT"]
employeeRoles=["paramedic","emt","engineer","officer"]   (these are CAPABILITIES / certs)
RIDE_UP_CAPABILITIES=["officer","engineer"]   (medical is license-only, not ride-up-able)
LICENSE_CAPABILITIES=["paramedic","emt"]  person-held, NOT rank-derived. Roster import MERGES
  these forward instead of overwriting, so an in-app paramedic grant survives re-import.
unitTypes=["Engine","Ladder","Medic","Batt","MOF","Tender","Brush","Rescue"]
UNIT_POSITION_REQUIREMENTS: Record<type, {role,label,cap,required?}[]>  (CAPABILITY-based now)
  cap = required capability ("officer"|"engineer"|"paramedic"|"emt"), array = any-of, null = any rank
  required:false = optional rider seat (doesn't count toward minimum staffing)
  Engine = Officer(officer)+Engineer(engineer) required + FF1..3(null, optional)  -> min 2, up to 5
GRAPH_SCOPES=["User.Read","User.ReadBasic.All"]; APP_CONFIG.schedulerApiScopes=["api://<clientId>/access_as_user"]
views: day|week|month; scheduleStatus: draft|published; shifts: A|B|C|null

Core entities:
Employee{id, entraId?, name, shift(A|B|C|null), title, certs[], rideUp[], email, isSupervisor, status}
  certs = rank-derived capabilities; rideUp = acting quals ABOVE rank (subset of RIDE_UP_CAPABILITIES),
  stored separately so roster re-import never wipes it. pin removed (Entra auth only).
Unit{id,name,type,minStaff,requiredCerts,onDemand,activeDates[],sortOrder,visible}
  sortOrder = board order. Front-line 1..8 = BC115,MOF115,L115,E115,M115,M115B,E116,M116.
  Everything else defaults to 100 (sorts after, then by name). byBoardOrder() is the ONLY
  ordering — never trust state.units array order, it comes from the API.
  NO unit.shift — apparatus have no platoon; whichever shift is on duty that DATE staffs them.
  onDemand=false -> runs every shift day. onDemand=true -> only on dates in activeDates[].
  migrateUnitShiftModel() strips legacy unit.shift on load. requiredCerts is VESTIGIAL for
  typed units (alerts come from UNIT_POSITION_REQUIREMENTS[type], not that field).
Trade{id,status,employeeId,partnerId,date,notes,type,createdBy}
OvertimePost{id,status,unitId,date,qualification,reportTime,applicants,approvedEmployeeId?}

Capabilities / seats:
personCapabilities(emp)=[...certs, ...rideUp]; seatAccepts(pos,emp) checks pos.cap vs caps (null=any)
resolvePerson(p)=live employee by id (assignment snapshots resolved to current record)
assignPeopleToSeats(unitType,people) greedy-fills seats (specific/required first) -> {seats,extra}
seatDropdownOptions(pos,unit,date): active, seat-eligible, NOT assignedEmployeeIdsForDate(date) (no double-booking)
  assignedEmployeeIdsForDate only counts assignments to EXISTING units (orphaned/deleted-unit ones ignored)

Auth flow (MSAL):
initMsal() silent (accts) -> loadRemoteStateAfterAuth() -> setAuthFromToken()
handleMsalLogin() popup -> loadRemoteStateAfterAuth() -> setAuthFromToken() -> render (NO save in API mode)
  API data needs a token, so it loads AFTER sign-in; hydrateAppState starts EMPTY in API mode and NEVER
  saves at startup (prevents empty state overwriting the server). Supabase mode unchanged.
setAuthFromToken -> syncEmployeeFromEntraProfile (ROSTER AUTHORITATIVE: only identity fields on existing recs)
Popup redirectUri = origin + "/blank.html" (registered in Azure as SPA URI)
D7FR Roster Import: Admin->Imports, accepts staff_contact.xlsx directly; matched by email; flags/skips
  DUPLICATES (in-file + already-in-roster); reads optional col5 "Ride-up" (Officer/Driver) via parseRideUpTokens.

Startup/persistence:
DOMContentLoaded -> hydrateAppState -> initMsal -> initializeControls -> render
serializableState persists: units, employees(incl certs+rideUp), trades, overtimePosts, notifications,
  auditLog, assignments, scheduleStatus, employeeFilter, activeSurface, activeAdminTab
loadRemoteState/saveRemoteState branch on usesSchedulerApi(): GET/PUT /api/scheduler/state/ (Bearer token)
  vs Supabase REST. applyPersistedState: migrateShiftNames + migrateEmployeeTitles + migratePersistedUnitTypes

Dates (America/Chicago, NEVER UTC):
todayIso() = current Central date, rolled back to previous day before 08:00 (0800-0800 shift day)
addDays/formatDate etc. anchor at noon to avoid tz date-shift

Staffing:
getStaffingAlerts(date) -> checkPositionStaffing(unit,people,positions): greedy, capability-based;
  only REQUIRED seats raise "danger" alerts (optional rider seats don't)

Units-per-date / on-demand service:
unitRunsOn(unit,date) / unitsForDate(date) replace every old `unit.shift===getShiftForDate(date)`
eligibleEmployeesForDate(date) = platoon on duty that date (supervisors see all, for OT)
inactiveOnDemandUnits(date) -> renderReserveTray(date) supervisor tray in DAY VIEW only
activateUnitForDate/deactivateUnitForDate write unit.activeDates; deactivate KEEPS assignments
  (audit-logged, persisted); unitServiceControlHtml + attachUnitServiceEvents wire the buttons
seedAssignments() is DEMO-ONLY and hard-disabled when usesSchedulerApi() — it fabricated
  180 days of capability-unchecked staffing that then persisted to Railway.
