TIME BLOCKS (partial tours) — migration 0013:
Assignment.start_minute/end_minute = MINUTES FROM THE UNIT'S TOUR START, so a full tour is
  0..unit.tour_minutes and nothing ever wraps midnight. First 4 hrs = 0..240; last 20 = 240..1440.
  unique_together is (employee,unit,date,start_minute) and the _write_state dedupe key matches —
  the old 3-tuple made "first 4 on, back for the last 2" impossible at the schema level.
On the wire they ride with the person like _pay/_src: `_start`, `_end`. A FULL TOUR SENDS
  NEITHER, so a whole-day payload is byte-identical to pre-partial-shift and old clients work.
SPA: blockOf(person,tour) / isFullTour / blockLabel(person,unit) / windowLabel(win,unit) /
  blocksOverlap (HALF-OPEN: 1200-1200 is a handoff, not a conflict) / tourGaps(people,tour) /
  tourCovered(people,tour) / minuteToClock(min,startHour) / minuteToTimeValue / timeValueToMinute.
30-MINUTE SLOTS: SLOT_MINUTES=30, snapToSlot(), inputs are step="1800", durationLabel() prints
  "4h"/"1.5h"/"20h". The department schedules in half hours; 0817 is a typo, not a shift.
GOTCHA: blockOf must NOT default _start and _end INDEPENDENTLY. A junk _start beside a real
  _end silently produced a four-hour block nobody typed. Either field unusable => whole block
  reads as a FULL TOUR (same rule server-side in _parse_block).
NAME COLLISION THAT ALREADY BIT: coverageGaps(startDate,days) is the OVERTIME scanner. The seat
  helpers are tourGaps/tourCovered. A duplicate top-level `function` declaration silently wins
  for the WHOLE FILE — mine hijacked every OT board call before it was renamed.

PER-UNIT TOUR SHAPE (admin / light duty) — migration 0014:
Unit gains scheduleClass ("operations"|"admin"), tourStartHour, tourMinutes, weekdays[] (Mon=0).
  Admin = 0800-1800 (600 min), Mon-Thu [0,1,2,3]. NOTHING hard-codes 1440 any more — it asks the
  unit: unitTourMinutes(unit) / unitTourStartHour(unit) / isAdminUnit(unit).
  Ten hours FILLS an admin seat while the same block on a rig is still 14 hours short.
visibleUnits() splits: operationsUnits() / adminUnits() / adminUnitsForDate(date). Admin units are
  DELIBERATELY excluded from unitsForDate(), printableUnits(), staffing alerts, the overtime board
  and the trade board — they are constant, follow none of the operations rules (no platoon, no
  mandatory OT, no PTO tour limits) and mixing them in clogs operations scheduling.
"Admin" view button -> renderAdminSchedule(range): the admin WEEK, Mon-Thu, plus an
  "On light duty this week" roster. Fri-Sun render greyed "Not an admin day" rather than vanishing.
UNIT_POSITION_REQUIREMENTS.Admin = 6 seats, cap:"admin", EVERY ONE required:false. An empty admin
  position is normal, not a staffing failure — a required seat there would raise a danger alert
  like an unstaffed engine. The board shows filled slots + ONE "Add person" row, not six dropdowns.
Cross-unit overlap compares MINUTES FROM MIDNIGHT (absoluteBlock), not each unit's own offset.
  Today both start at 0800 so the numbers agree; the moment one does not, an unconverted compare
  declares somebody free when they are not.

ABSENCES (PTO etc.) — migrations 0016/0017/0018:
Assignment.absence_code ("PTO"|"SICK"|"FMLA"|"LTD") + absence_note + absence_no_backfill.
  Wire: `_off`, `_offNote`, `_noFill`.
AN ABSENCE BLOCK KEEPS ITS HOURS (payroll) BUT COVERS NO SEAT. That is what makes minimum
  staffing honest: the rig reads SHORT and an "Off this tour" roster under the seats
  (offRosterHtml) says who and why. assignPeopleToSeats pulls them out BEFORE seating.
LTD IS LIGHT DUTY, not long-term disability. It is NEVER picked from the dropdown — it is
  DERIVED live from the member's light-duty date range by lightDutyBlockFor(), carries
  _derivedLightDuty and _noFill (nobody is called in for light duty; admin owns that payroll),
  and gets no × because the date range owns it. An explicit PTO entry WINS over it.
ABSENCE_REASONS (the pickable list) = PTO / SICK / FMLA only. Admin enters LTD payroll.
An unknown absence code or platoon reads as WORKING / unassigned, NEVER as "off" — a typo must
  not silently take somebody off a rig the board then reports as covered.
Payroll CSV (/api/scheduler/assignments/export.csv) gained start,end,hours,absence,absence_note.
  Without them payroll reads a 4-hour block, or PTO hours, as a full tour.
"Open these hours for backfill?" has NO DEFAULT — the chief must answer. "No" leaves the seat
  visibly short but keeps the hours off the OT board (the gap scanner skips no-fill windows).
applyTimeOff({personId,unitId,from,to,start,end,reason,note,openForBackfill}) writes ONE ROW PER
  TOUR across a date range, and only touches dates the person was ALREADY scheduled on that unit
  — a date they were never on is skipped and counted, never invented. A 48 stays two rows.

LIGHT DUTY (Employee) — migration 0015:
light_duty_start / light_duty_end / light_duty_note. A DATE RANGE, not a flag: the board is built
  weeks ahead, so a chief staffing three weeks out has to be stopped then, not only today.
  Blank end = OPEN-ENDED on purpose ("nobody set a return date" must not read as back to full duty).
onLightDuty(emp,date) / lightDutyReason(emp,date) / employeeAvailableForUnit(emp,unit,date).
Blocking the PICKERS is not enough: somebody already on the schedule keeps filling those seats.
  lightDutyBlockFor() vacates operations seats live from the range. Admin seats are untouched —
  that is where they work. Dates only + a short operational note; NOT a medical record.

GOTCHA THAT ALREADY BIT ONCE: applyPersistedState() is a KEY-BY-KEY ALLOWLIST. The
  API sent payCodes down correctly and the SPA dropped them, so the picker rendered
  nothing everywhere. Any new key in the server payload MUST be added there too, or

  The copy is conditional (Array.isArray) so a localStorage restore, which has no
  payCodes key, cannot blank a list already loaded from the API.
THIRD GOTCHA, SAME FAMILY: assignPeopleToSeats() returns { pos, person } -- the
  seat DEFINITION is nested under `pos`. seat.label / seat.role / seat.required are
  all undefined on the wrapper. printSeatRows read them off the wrapper and printed
  "undefined" as every seat label, and since `undefined !== false` it also marked
  every optional rider seat required. Read seat.pos.label and seatIsRequired(seat.pos).
FOURTH GOTCHA, SAME FAMILY -- THE ACTUAL "undefined" IN THE NOTIFICATION CENTER:
  queueNotification() sets `title` and `time` on the local object, but
  NotificationSerializer has NEITHER (its fields are id, recipientId, channel,
  subject, message, status, relatedKind, relatedId, createdBy, createdAt). Both
  vanish on the first round trip, so everything older than the current session
  rendered "undefined" over the message and "EMAIL • undefined" under it. Fixed by
  DERIVING at render: notificationTitle() (subject || channel label) and
  notificationTime() (local time || createdAt). Rule: never render a raw property
  the serializer does not list -- it will look right until the next reload.
AUDIT/NOTIFICATION TEXT IS FROZEN AT WRITE TIME: those strings are stored, not
  re-rendered, so a lookup that misses bakes the word "undefined" into the record
  permanently. Use unitLabel(id) (falls back to the raw id), never a bare
  `unitById(id)?.name`, in anything that becomes stored text. renderAuditLog()
  escapes actor/message/time -- they carry names and typed notes into innerHTML.
SECOND GOTCHA, SAME FAMILY: resolvePerson() returns the live ROSTER record, which
  has NO _pay/_payNote/_payFor -- those live on the stored assignment. printSeatRows
  mapped straight through it and printed an empty code column while the board showed
  codes fine (it reads the stored objects). Anything that resolvePerson()s an
  assignment before reading transport fields must merge them back explicitly.

PAYLOAD SIZE IS A CORRECTNESS ISSUE, NOT AN OPTIMISATION:
auditLog + notifications are append-only and grew to 18 MB with ZERO assignments. At that size
  the PUT died before Django answered (browser reported it as a CORS error, not a 413/502) AND
  localStorage threw QuotaExceededError inside persistAppState's catch — so nothing saved by any
  route, silently, for hours. HISTORY_KEEP=250 caps both in serializableState() and addAudit();
  server caps the GET at AUDIT_HISTORY_LIMIT=250 (_serialize_state). Full history stays in the
  AuditEntry table / /api/scheduler/audit/. NEVER send unbounded collections through /state/.
#export-audit-btn (drawer -> Activity) -> exportAuditLog(): fetches
  /api/scheduler/audit/export.csv WITH the bearer token and triggers a download. A plain <a href>
  cannot work — the endpoint is authenticated.
saveLocalState() swallows quota errors — it is a best-effort backup and must never break the
  remote save path.

The EDITOR COLUMN is sticky, not the panel inside it: .secondary-column gets position:sticky +
  align-self:start (top:84px). A sticky CHILD can only travel within its own parent, and with
  .admin-grid align-items:start that column is exactly content height — so a sticky panel there
  had nowhere to go, scrolled away, and clicking Edit appeared to do NOTHING. Sticking the column
  works because its containing block is the grid, which is as tall as the roster beside it.
Edit uses scrollIntoView({block:"nearest"}) — scrolls ONLY when the editor is off screen. A hard
  block:"start" threw the supervisor back to the top of a 71-person list after every edit; a
  breakpoint guard silently did nothing when the sticky broke. "nearest" is correct in both.
