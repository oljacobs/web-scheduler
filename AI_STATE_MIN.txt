Core entities:
Employee{id, entraId?, name, shift(A|B|C|null), title, certs[], rideUp[], email, isSupervisor, status}
  certs = rank-derived capabilities; rideUp = acting quals ABOVE rank (subset of RIDE_UP_CAPABILITIES),
  stored separately so roster re-import never wipes it. pin removed (Entra auth only).
Unit{id,name,type,minStaff,requiredCerts,onDemand,activeDates[],sortOrder,visible}
  sortOrder = board order. Front-line 1..8 = BC115,MOF115,L115,E115,M115,M115B,E116,M116.
  Everything else defaults to 100 (sorts after, then by name). byBoardOrder() is the ONLY
  ordering — never trust state.units array order, it comes from the API.
  NO unit.shift — apparatus have no platoon; whichever shift is on duty that DATE staffs them.
  onDemand=false -> runs every shift day. onDemand=true -> only on dates in activeDates[].
  migrateUnitShiftModel() strips legacy unit.shift on load. requiredCerts is VESTIGIAL for
  typed units (alerts come from UNIT_POSITION_REQUIREMENTS[type], not that field).
Trade{id,status,employeeId,partnerId,date,notes,type,createdBy}
Notification{id,recipientId,channel(email|sms|in_app),subject,message,status(queued|sent|failed|
  skipped),relatedKind,relatedId,createdBy,time}  — an OUTBOX, not a log. Nothing sends yet;
  rows persist server-side as "queued" so wiring SMTP/SMS later is a transport change only.
  Django Notification model + migration 0006. Previously notifications were NEVER serialized:
  the SPA sent them, the server discarded them, nothing came back.
OvertimePost{id,status(requested|open|awarded|closed),unitId,date,role,requiredCap,qualification,
  reportTime,applicants[],approvedEmployeeId?,notifiedAt}
  The OPPORTUNITY is the GAP (unit+date+seat role); the post records that it is open and, once
  notified, that qualified people were told. Applying to an un-announced gap creates the post as
  "requested" so supervisors see demand — that is how "sign up for shifts not yet sent out" works.

AUDIT LOG — two bugs, both fixed, do not reintroduce:
1) AuditEntrySerializer exposed the DB pk as "id" while _write_state deduped on source_id, so
   every round trip re-created the ENTIRE log. 118,874 rows from a few dozen real actions.
   The serializer now maps id -> source_id, and _write_state refuses entries with no id.
2) Sign-in was audited on every silent token refresh (122/day). Removed. See the AUDIT POLICY
   comment above addAudit(): log schedule-affecting changes, never authentication or navigation.
Full history export: GET /api/scheduler/audit/export.csv (auth required) + Activity tab button.

PAYLOAD SIZE IS A CORRECTNESS ISSUE, NOT AN OPTIMISATION:
auditLog + notifications are append-only and grew to 18 MB with ZERO assignments. At that size
  the PUT died before Django answered (browser reported it as a CORS error, not a 413/502) AND
  localStorage threw QuotaExceededError inside persistAppState's catch — so nothing saved by any
  route, silently, for hours. HISTORY_KEEP=250 caps both in serializableState() and addAudit();
  server caps the GET at AUDIT_HISTORY_LIMIT=250 (_serialize_state). Full history stays in the
  AuditEntry table / /api/scheduler/audit/. NEVER send unbounded collections through /state/.
#export-audit-btn (drawer -> Activity) -> exportAuditLog(): fetches
  /api/scheduler/audit/export.csv WITH the bearer token and triggers a download. A plain <a href>
  cannot work — the endpoint is authenticated.
saveLocalState() swallows quota errors — it is a best-effort backup and must never break the
  remote save path.

  PASSIVE ("Saved 2:14 PM" / "Saving…") via renderSaveIndicator(). saveSupervisorEdits() was a
  placebo — it only logged + toasted — and is DELETED.
state.isLoadingRemote gates a skeleton in renderSchedule(); set in loadRemoteStateAfterAuth
  (finally-cleared). API mode starts empty, so without it a blank board reads as data loss.
handlePublish() confirms first and reports unfilled required seats in the prompt + audit line.
publish-btn is button-primary only while scheduleStatus==="draft", else secondary.
:focus-visible rules exist now — there were ZERO focus styles before; custom button CSS had

Week/month coverage is NOT colour-only: .cal-warn/.cal-ok prepend ⚠/✓ to the seat count.

Staffing templates (per-platoon standing crews):
state.staffingTemplates=[{unitId,shift:"A|B|C",seats:{roleKey:employeeId}}]  (roles = pos.role
  from UNIT_POSITION_REQUIREMENTS). Django: StaffingTemplate(unit,shift,seats) unique(unit,shift),
  migration 0005; round-trips through /state/ as "staffingTemplates" (upsert + prune like units).
PROVENANCE: each stored assignment person carries _src "template"|"manual"; Django
  Assignment.source persists it. markManual() stamps the WHOLE unit-day on any human edit.
  isTemplateGenerated(people) = non-empty AND every row template -> only those may be overwritten.
crewFromTemplate(unitId,date) drops archived/missing people so the seat reads as an OPEN GAP.
  seatAccepts() also returns false for archived — that is what makes departed staff visible.
previewTemplatePush(days) is a DRY RUN -> {created,replaced,skippedManual,noTemplate,dates};
  applyTemplatePush(days) confirms with those numbers, writes, and logs ONE audit entry.
Default horizon TEMPLATE_PUSH_DEFAULT_DAYS=180. Activating an on-demand unit PROMPTS to fill
  from that platoon's template (never silent).
Admin -> Templates tab: template-unit/template-shift/template-seats/template-push-*.
renderTemplateEditor() OWNS the seat-select binding (calls attachTemplateSeatEvents at its end).
  It replaces template-seats innerHTML, which destroys the old listeners — the unit and platoon
  dropdowns previously re-rendered WITHOUT re-binding, so the seat selects were inert after any
  platoon change and nothing could be saved. Never bind from a caller: that double-fires.
A push only covers units ON DUTY that date, so reserve (onDemand) units are never written by a
  push — their crews apply via the "Fill from template?" prompt on activation. When a push finds
  nothing, applyTemplatePush names WHICH case it is (no seats set / reserve-only / all manual)
  instead of a bare "nothing to push".
BACKEND PRUNE GUARD (scheduler/views.py _write_state): a Unit/Employee missing from the payload
  is deleted ONLY if it has no assignments; otherwise it is hidden/archived. Assignments are
  rebuilt only for units present in the payload. Deleting cascades to Assignment, and a stale
  browser tab wiped MOF115 twice before this existed — do not "simplify" it back.

Overtime / coverage (drawer -> Coverage tab, ONE list for both roles):
coverageGaps(startDate,days) -> every unfilled REQUIRED seat with the capability it needs, derived
  from the schedule (never typed in, so a post can't ask for the wrong qualification).
gapKey(unitId,date,role) identifies a gap; overtimePostForGap() finds its post.
eligibleForGap(gap) = credentialed via seatAccepts + active + NOT already assigned that date
  (same-day double-booking is barred department-wide, at apply AND at award).
notifyGap / applyForGap / withdrawFromGap / awardOvertime(postId,employeeId) / declineApplicant.
state.coverageShift = "mine"|"A"|"B"|"C"|"all" — platoon filter on the Coverage tab. A gap's platoon
  is getShiftForDate(gap.date), a property of the DATE not the truck. Defaults to "mine" so each
  battalion chief sees only their own platoon; stored as "mine" (not the letter) so the filter
  follows whoever is signed in. Filters the list, the summary AND the badge.
awardOvertime writes a REAL Assignment (markManual) — awarding used to change nothing on the board.
Supervisors CHOOSE the winner. approveQueueItem() no longer touches overtime: it used to set
  approvedEmployeeId = applicants[0], and createOpenShift() FABRICATED three applicants, so shifts
  were awarded to people who never volunteered. Both deleted.

`node --check` only checks SYNTAX. It happily passed while addEventListener("click", createOpenShift)
  referenced a deleted function, which would have thrown in wireEvents() and killed startup.
  Verify named handlers resolve after removing any function.
